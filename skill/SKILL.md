# Codify Dev - 设计转代码

## 核心原则

> **截图看布局，骨架定边界，JSON 取样式。三者协同，缺一不可。**

### 还原质量 = 视觉还原 + 代码质量

| 维度     | 要求                          |
| -------- | ----------------------------- |
| 视觉还原 | 样式从 `customStyle` 精确提取 |
| 代码质量 | 结构合理、接口清晰、数据驱动  |

两者缺一不可。视觉完美但代码硬编码，不算完成还原。

> 严格遵守代码生成规范 [codegen-rules.md](references/codegen-rules.md)

---

## 理解三种数据源

| 数据源   | 告诉你什么                             | 不告诉你什么                |
| -------- | -------------------------------------- | --------------------------- |
| **截图** | 视觉效果、颜色感知、间距比例、整体氛围 | 精确数值、层级结构、节点 ID |
| **骨架** | 组件边界、布局方向、重复模式、节点层级 | 具体样式、颜色、字体大小    |
| **JSON** | 精确 CSS 值、节点属性、资源 ID         | 视觉上下文、设计意图        |

**协同使用**：

- 截图 + 骨架 → **理解设计意图，规划组件拆分**
- 骨架 + JSON → **精确实现，确保不遗漏节点**
- 截图 + JSON → **验证还原效果**

## 工作流程

### Step 1. 建立视觉认知（如有截图）

用户上传截图时：

- 识别主要区域和层级关系
- 观察视觉模式（重复元素、对齐方式）
- 注意装饰细节（阴影、圆角、渐变）

> 无截图时跳过此步，直接进入 Step 2。

### Step 2. 获取结构骨架

```bash
curl -s -X POST http://127.0.0.1:13580/get_design \
  -H "Content-Type: application/json" \
  -d '{"node_id": "节点ID", "mode": "skeleton"}'
```

**骨架标记速查**：

- `[H]`/`[V]` → flex 水平/垂直布局
- `×N` → 重复 N 次，只实现模板
- `ID` → 关键节点，可单独获取
- `:` → 简单子节点，合并显示
- `ICON` → 需要下载 SVG 的图标节点
- `TEXT "..."` → 文本节点及内容预览

### Step 3. 复杂度判断

获取骨架后，根据层级和区域数量判断复杂度：

| 条件               | 路径                                                        |
| ------------------ | ----------------------------------------------------------- |
| 层级 ≤3 且 区域 ≤2 | A：Step 4 整体实现                                          |
| 层级 >3 或 区域 >2 | B：**必须阅读文档并执行** [phased-workflow.md](references/phased-workflow.md) |

**路径 B 约束**：

| 禁止                 | 必须                        |
| -------------------- | --------------------------- |
| 一次性生成所有代码   | 逐组件生成代码              |
| 遗漏骨架中的关键节点 | 跟踪每个组件/区域的实现状态 |
| 未完成所有组件就结束 | 所有组件完成后才算实现完成  |

---

### Step 3.5 接口设计（强制）

生成代码前，先设计组件输入接口。

| 类型         | 判断标准           | 处理方式               |
| ------------ | ------------------ | ---------------------- |
| 业务数据     | 运行时从接口获取   | Props（必填）          |
| 可配置文案   | 复用时可能需要修改 | Props（可选 + 默认值） |
| 固定 UI 文案 | 复用时不会改变     | 硬编码                 |

**Props 结构**：语义相关字段组合为对象，重复结构（×N）设计为对象数组

**预览验证**：在调用层传入 mock 数据（值来自设计稿）

---

### Step 4. 路径 A：整体实现（仅限简单设计）

> 如果Step 3 判断为复杂，则跳过此步骤，阅读并按照[phased-workflow.md](references/phased-workflow.md)执行复杂设计。

```bash
curl -s -X POST http://127.0.0.1:13580/get_design \
  -H "Content-Type: application/json" \
  -d '{"node_id": "节点ID"}'
```

获取 JSON 后，遵循 [codegen-rules.md](references/codegen-rules.md) 生成代码。

---

### Step 5. 下载资源

> **禁止跳过此步骤**。禁止用 emoji/占位符/纯色代替图标和图片。

**资源识别**：

| 类型       | 识别方式                                    | 格式 |
| ---------- | ------------------------------------------- | ---- |
| 图标       | `type: "ICON"`                              | SVG  |
| 图片背景   | `customStyle` 含 `url(<path-to-image>)`     | PNG  |
| 图片占位符 | `RECTANGLE` + `object-fit: cover`（无 url） | PNG  |

**强制要求**：

- 必须下载组件代码中使用到的图标和图片背景等资源
- 对于 RECTANGLE + object-fit: cover 的隐式图片，用节点 ID 下载 PNG

**下载命令**：

```bash
node skill/scripts/download-assets.cjs --nodes '[
  {"nodeId":"123:456","outputPath":"/path/to/icon.svg","format":"svg"},
  {"nodeId":"789:012","outputPath":"/path/to/bg.png","format":"png"}
]'
```

---

### Step 6. 终态验证

> **禁止跳过**。禁止在此步骤前宣布"实现完成"。

| 禁止                                 | 必须                                |
| ------------------------------------ | ----------------------------------- |
| 存在未完成组件时宣布"完成"           | 所有组件/区域状态为完成             |
| 遗漏骨架关键节点                     | 骨架节点均已实现                    |
| 硬编码业务数据                       | 业务数据通过 Props 传入             |
| 重复结构硬编码                       | 重复结构（×N）使用数组 Props + 循环 |
| 图标/图片使用占位符、emoji、纯色代替 | 所有资源已下载，路径真实            |
| 资源引用方式与项目已有代码不一致     | 资源引用方式与项目已有代码一致      |

**验证不通过时**：列出未完成项，询问用户是否继续

## 错误处理

| 错误码          | 处理                     |
| --------------- | ------------------------ |
| `NOT_CONNECTED` | 提示启用 Codify Dev 扩展 |
| `NO_SELECTION`  | 提示选择节点             |
| `TIMEOUT`       | 重试（最多 3 次）        |

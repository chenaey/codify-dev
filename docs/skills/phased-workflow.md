# 分步实现流程

> **路径 B 专用**：当 SKILL.md Step 3 判定为"复杂"时，必须执行本流程。

## 核心约束
必须：先理解 → 再规划 → 逐个思考 → 逐个实现

| 禁止               | 必须                       |
| ------------------ | -------------------------- |
| 一次性生成所有代码 | 逐组件生成代码             |
| 跳过规划直接写代码 | 先输出组件规划，再逐个实现 |
| 实现部分组件就结束 | 所有组件完成后才算结束     |

---

## Phase 1: 理解骨架

用一段话描述骨架结构：

- 主要区域及节点 ID
- 重复模式（×N）
- 布局方向

> 骨架中每个关键 ID 都要提及，防止遗漏。

---

## Phase 2: 组件规划

输出组件规划（含 Props）：

> 从骨架推导数据接口，设计稿值作为示例数据。

```
组件规划：
1. Card (子组件) - 单个卡片 | Props: { icon, title, onClick? }
2. CardList (13:4382) - 卡片列表 ×3 | Props: { items: CardItem[] }
3. Header (13:3811) - 顶部导航 | Props: { title }
4. Footer (17:6940) - 底部信息 | 无 Props
```

**实现顺序**：被依赖的组件先实现（Card → CardList）

---

## Phase 3: 逐个实现

- 复杂设计必须拆分为多个合理组件文件，职责单一，同时组件设计合理的输入接口，最终组装。
- 注意组件跟组件之间的边界关系 边距信息等 禁止遗漏关键样式

### 3.1 获取完整 JSON

```bash
curl -s -X POST http://127.0.0.1:13580/get_design \
  -H "Content-Type: application/json" \
  -d '{"node_id": "13:4382"}'
```

### 3.2 逐组件实现

对每个组件：分析结构 → 下载资源 → 生成代码 → 标记完成

阅读并遵循 [codegen-rules.md](codegen-rules.md)

---

## Phase 4: 组装验证

1. 创建页面入口，组装所有组件
2. 确认骨架中每个关键节点都已实现
3. 返回 SKILL.md Step 6 终态验证
